Project Layout

Project Layout is a small utility library for describing and working with conventional project directory layouts, including source code, resources, tests, documentation, and related project files. It gives build tooling and plugins a consistent way to locate and process those files across Maven, Gradle, JavaScript, Python, and convention-based projects.

The library models a project root and exposes root-relative locations for production sources, tests, documents, and optional modules. The layout model applies to source code as well as documentation, project-site content, configuration, and other files discovered while a project is inspected; callers resolve each returned path against the configured root before accessing it.

Package overview

org.machanism.machai.project

This package contains the public entry points for identifying a project's ecosystem and traversing its directory tree. ProjectLayoutManager checks project metadata in a defined order—Maven, Gradle, JavaScript, Python, then the generic fallback—and configures the selected ProjectLayout with the supplied root. ProjectProcessor uses that layout to recurse through declared modules or delegates a leaf project to {@code processFolder(ProjectLayout)}.

org.machanism.machai.project.layout

This package defines the common layout contract and ecosystem-specific implementations. A layout reports the configured project directory, root-relative source, test, and documentation folders, optional module paths, project identity information, and utility operations for relative paths and directory discovery. Recursive directory discovery excludes known dependency, build, cache, IDE, and temporary directories such as node_modules, .git, build, target, and .machai where the implementation applies those conventions.

  • MavenProjectLayout reads pom.xml metadata, exposes Maven source and test roots, derives project identity, and resolves reactor modules.
  • GradleProjectLayout inspects Gradle projects through the Gradle Tooling API and represents child projects and their conventional folders.
  • JScriptProjectLayout reads package.json and resolves JavaScript workspace patterns against the filesystem.
  • PythonProjectLayout recognizes Python projects from pyproject.toml and related conventions.
  • DefaultProjectLayout supplies conventional folders when no supported ecosystem-specific metadata is present.
  • PomReader parses Maven models and performs the lightweight property replacement needed by Maven layout detection.

Typical usage

  1. Pass an existing project root to {@code ProjectLayoutManager.detectProjectLayout(projectDir)}.
  2. Query the returned layout with {@code getSources()}, {@code getTests()}, {@code getDocuments()}, and, when applicable, {@code getModules()}.
  3. Resolve each root-relative result against {@code getProjectDir()} before reading or writing source code, documentation, site content, or other project files.
  4. For recursive processing, subclass {@code ProjectProcessor}, implement {@code processFolder(ProjectLayout)}, and call {@code scanFolder(projectDir)}.

Usage examples

Detect a layout and inspect folders

{@code File projectDir = new File("C:/path/to/project");}
{@code ProjectLayout layout = ProjectLayoutManager.detectProjectLayout(projectDir);}
{@code Collection<String> sources = layout.getSources();}
{@code Collection<String> tests = layout.getTests();}
{@code Collection<String> documents = layout.getDocuments();}

Process a repository tree

{@code ProjectProcessor processor = /* custom implementation */ null;}
{@code processor.scanFolder(new File("C:/path/to/repo"));}

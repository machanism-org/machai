Project Layout

Project Layout is a small utility library for describing and working with conventional project directory layouts (sources, resources, tests, documentation, and other project files) in a consistent way. It is intended for build tooling and plugins that need to locate well-known folders reliably across different projects.

The API treats the configured project directory as a root and reports paths relative to that root. It supports all relevant project-file categories, including source code, documentation, project-site content, configuration, resources, tests, and files discovered while a repository is inspected. Callers resolve returned paths against {@code ProjectLayout.getProjectDir()} before accessing the filesystem.

Package structure

org.machanism.machai.project

This package provides the project-inspection entry points. {@link org.machanism.machai.project.ProjectLayoutManager} detects a layout from project metadata in a deterministic order: Maven ({@code pom.xml}), Gradle ({@code build.gradle}), JavaScript or TypeScript ({@code package.json}), Python ({@code pyproject.toml}), and finally the generic fallback for an existing directory. A missing root produces a {@link java.io.FileNotFoundException}.

{@link org.machanism.machai.project.ProjectProcessor} separates detection from processing. It scans a root, recursively visits module paths reported by the selected layout, and delegates a leaf project to {@code processFolder(ProjectLayout)}. Subclasses can therefore implement repository-specific handling without duplicating ecosystem detection or module traversal.

org.machanism.machai.project.layout

This package defines {@link org.machanism.machai.project.layout.ProjectLayout}, the common abstraction for a project root, source roots, test roots, documentation roots, optional modules, project identity, and path utilities. Layout implementations express locations as root-relative strings and may expose child projects declared by build metadata. The package also provides recursive filesystem discovery that excludes common dependency, build, cache, IDE, and temporary directories through {@code ProjectLayout.getExcludeDirs()}.

  • {@link org.machanism.machai.project.layout.MavenProjectLayout} reads {@code pom.xml}, Maven coordinates, modules, source and resource directories, test directories, documentation inputs, and parent identity. Maven defaults are used when source directories are not explicitly set.
  • {@link org.machanism.machai.project.layout.GradleProjectLayout} uses the Gradle Tooling API to obtain child projects and exposes the conventional {@code src/main}, {@code src/test}, and {@code src/site} locations.
  • {@link org.machanism.machai.project.layout.JScriptProjectLayout} reads {@code package.json} and expands array-form {@code workspaces} glob patterns into module directories containing a package descriptor.
  • {@link org.machanism.machai.project.layout.PythonProjectLayout} recognizes a Python project when a valid {@code pyproject.toml} identifies a non-private project; its source, test, and documentation accessors currently return empty collections.
  • {@link org.machanism.machai.project.layout.DefaultProjectLayout} supplies the fallback model, treating non-excluded immediate subdirectories as modules and returning empty collections for ecosystem-specific roots.
  • {@link org.machanism.machai.project.layout.PomReader} parses Maven models and performs the model-reading support required by Maven layout detection.

Typical usage

  1. Provide an existing root to {@code ProjectLayoutManager.detectProjectLayout(projectDir)}.
  2. Query the result with {@code getSources()}, {@code getTests()}, {@code getDocuments()}, and, when applicable, {@code getModules()}.
  3. Resolve each returned path against {@code getProjectDir()} before reading or writing source code, resources, documentation, site content, configuration, or other project files.
  4. For recursive processing, subclass {@code ProjectProcessor}, implement {@code processFolder(ProjectLayout)}, and call {@code scanFolder(projectDir)}.

Examples

Detect a layout and inspect its root-relative locations

{@code File projectDir = new File("path/to/project");}
{@code ProjectLayout layout = ProjectLayoutManager.detectProjectLayout(projectDir);}
{@code Collection<String> sources = layout.getSources();}
{@code Collection<String> tests = layout.getTests();}
{@code Collection<String> documents = layout.getDocuments();}

Process a repository tree

A concrete processor implements {@code processFolder(ProjectLayout)} and can then scan a root: {@code processor.scanFolder(new File("path/to/repository"));}. A multi-module layout causes each declared module to be scanned recursively; a leaf layout is passed directly to the callback.

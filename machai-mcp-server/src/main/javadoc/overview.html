Machai MCP Server

Machai MCP Server is a server implementation for the Model Context Protocol (MCP) using the Machai AI framework. It integrates externally supplied GenAI tools and supports both HTTP and STDIO interfaces for AI-powered tool execution and orchestration. The module does not publish tools of its own; applications add libraries that implement Machai function tools, prompts, and, for stateless HTTP, resources. Machai MCP Server supports all types of project files, including source code, documentation, project-site content, and other relevant files.

Purpose

The server discovers Machai function tools through the configured tool-loading mechanism and exposes them as MCP tool specifications and synchronous call handlers. The STDIO and streamable HTTP transports also expose supplied prompts, while stateless HTTP exposes supplied prompts and resources. This makes the module suitable for local process integrations and remote MCP deployments backed by Jetty, while keeping transport handling separate from tool implementation.

Package Structure

The {@link org.machanism.machai.mcp.server} package contains the executable entry point, shared server abstractions, transport-specific implementations, and adapters that convert Machai tool metadata into MCP specifications. Its public API is intended to be used by applications that supply compatible Machai tool providers rather than by applications that define tools directly in this module.

The package-level API is organized around a common lifecycle: a server selects a transport, a {@code FunctionToolsLoader} discovers the available Machai functions, and a transport adapter registers each function as an MCP tool. The adapter also maps parameter descriptors to JSON Schema properties and translates successful and failed function invocations into MCP tool results. This separation lets the same tool-loading and invocation model serve process-based STDIO clients and HTTP clients without coupling tool implementations to a transport.

  • Server entry point: {@link org.machanism.machai.mcp.server.McpServer} parses command-line options, loads configuration, and starts the appropriate mode. Without a port it starts STDIO; with a port it starts HTTP. The {@code --session} option selects streamable HTTP instead of stateless HTTP.
  • Common server base: {@link org.machanism.machai.mcp.server.AbstractMcpServer} defines project-directory handling, the enabled-tool configuration filter, lifecycle hooks, and the tool-specification builder contract.
  • HTTP infrastructure: {@link org.machanism.machai.mcp.server.AbstractHttpMcpServer} configures the Jetty server, connector, servlet context, and HTTP transport servlet used by remote deployments.
  • HTTP server modes: {@link org.machanism.machai.mcp.server.HttpStatelessMcpServer} provides stateless synchronous HTTP handling with tools, prompts, and resources, while {@link org.machanism.machai.mcp.server.HttpStreamableMcpServer} provides streamable synchronous HTTP handling with tools and prompts. Their corresponding adapters are {@link org.machanism.machai.mcp.server.HttpStatelessGenericGenaiAdapter} and {@link org.machanism.machai.mcp.server.HttpStreamableGenericGenaiAdapter}.
  • STDIO server mode: {@link org.machanism.machai.mcp.server.StdioMcpServer} exposes MCP over standard input and output, using {@link org.machanism.machai.mcp.server.StdioGenaiAdapter} for process-based clients.
  • Tool integration: {@link org.machanism.machai.mcp.server.GenericGenaiAdapter} registers Machai GenAI tools, builds JSON schemas from parameter descriptors, routes MCP calls to Machai {@code ToolFunction} instances, adds session context for synchronous exchanges, and serializes results for MCP clients.
  • Prompt and resource integration: {@link org.machanism.machai.mcp.server.AbstractPromptGenaiAdapter} supplies the shared prompt-registration workflow used by the STDIO and HTTP adapters. The stateless HTTP adapter additionally registers resources and invokes their functions when clients request their configured URIs.
  • Startup failures: {@link org.machanism.machai.mcp.server.McpServerStartupException} represents failures reported while an HTTP server is being built or started.

Runtime Behavior

During startup, the selected server creates a {@code FunctionToolsLoader} and applies the available Machai tools through {@link org.machanism.machai.mcp.server.GenericGenaiAdapter}. The optional {@code enabledTools} configuration property limits registrations by tool name. Each parameter descriptor becomes a property in an MCP-compatible JSON schema, including requiredness, type, description, and, for optional parameters, a default. Transport adapters translate supported prompt definitions into MCP prompt specifications; the stateless HTTP adapter also translates resource definitions. On invocation, an adapter converts request arguments to JSON, adds the MCP session identifier for a synchronous exchange, invokes the underlying function with the project directory and configuration, and returns its value as text or serialized JSON. Exceptions produce MCP tool results marked as errors.

Usage

Add one or more libraries that provide Machai function tools and prompts to the runtime class path, then start the application through {@link org.machanism.machai.mcp.server.McpServer}. The server loads the configured providers before it starts listening, so this module alone does not make application-specific tools available. Unless {@code -c} or {@code --config} is supplied, it attempts to load {@code mcp.properties}; an explicitly requested configuration file must be readable. Supported command-line options are:

  • {@code -h}, {@code --help}: display command-line help.
  • {@code -d}, {@code --projectDir}: specify the project directory used by loaded tools.
  • {@code -n}, {@code --name}: set the MCP server name.
  • {@code -c}, {@code --config}: specify the Machai properties-file path.
  • {@code -v}, {@code --version}: set the MCP server version.
  • {@code -p}, {@code --port}: run as an HTTP MCP server on the given port.
  • {@code -s}, {@code --session}: use streamable HTTP server mode when running over HTTP.

If no port is provided, the server uses STDIO mode. If a port is provided, the server uses HTTP mode; stateless HTTP is the default and streamable HTTP is enabled with {@code --session}. Use {@code enabledTools} in the server configuration to register only selected discovered tool names. The value may contain names separated by spaces, commas, semicolons, or other whitespace.

Extensibility

The implementation separates transport concerns from tool registration. New transport modes can extend {@link org.machanism.machai.mcp.server.AbstractMcpServer} or {@link org.machanism.machai.mcp.server.AbstractHttpMcpServer} and provide a suitable tool-specification builder and adapter. Additional GenAI tools and prompts can be supplied through Machai's tool-loading mechanism and are exposed to MCP clients without changing the server entry point. Resource support requires a transport adapter that registers resource specifications. Implementations should preserve the MCP schema and error-result behavior established by the supplied adapters.

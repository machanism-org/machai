Ghostwriter

Ghostwriter is an advanced documentation engine that automatically scans, analyzes, and assembles project documentation using embedded guidance tags and AI-powered synthesis.

Ghostwriter supports all types of project files, including source code, documentation, project-site content, PlantUML diagrams, scripts, configuration, and standalone guidance files.

Purpose and design

Ghostwriter is a repository-aware documentation and workflow engine. It discovers @guidance directives, turns them into mandatory structured instructions, enriches requests with project-layout and runtime metadata, and applies generated results to the selected files.

The command-line entry point, {@code org.machanism.machai.gw.processor.Ghostwriter}, supports both guidance processing and declarative Act workflows. Acts are reusable TOML prompt definitions with defaults, inheritance, user inputs, and ordered episodes.

Architecture

Processors coordinate traversal and provider execution, reviewers extract format-specific guidance, and tools expose controlled host capabilities. A request can include instructions, prompts, public configuration values, YAML front matter, included prompt fragments, project context, and registered tools.

Package overview

org.machanism.machai.gw.processor

This package provides project traversal and AI-backed processing. {@code AbstractFileProcessor} supplies recursive module discovery, filtering, exclusions, non-recursive scans, and delegation to subclasses. {@code AIFileProcessor} selects files or folders using paths, {@code glob:} patterns, or {@code regex:} patterns and submits enriched requests to the configured provider.

{@code GuidanceProcessor} extracts guidance from supported files, preserves markers in their original locations, optionally processes files without guidance using a default prompt, and records results. {@code ActProcessor} loads Acts from classpath resources, local paths, or HTTP(S), applies inherited configuration, binds inputs, and executes selected prompts. {@code Episodes} supports ordered, selected, repeated, skipped, and jumped execution, including Markdown-heading episode names.

org.machanism.machai.gw.reviewer

This package defines the {@code Reviewer} extension point and format-specific adapters for Java, Markdown, HTML/XML, TypeScript, Python, PlantUML, and standalone {@code @guidance.txt} files. Reviewers recognize the syntax of their format, read UTF-8 content, and return a normalized prompt fragment or {@code null}. {@code JavaReviewer} gives guided {@code package-info.java} files package-level context, while {@code TextReviewer} uses the containing directory as context.

org.machanism.machai.gw.tools

This package exposes project-bound function tools for file operations, validated command execution, web and REST access, Act management, guidance processing, and project-context variables. Supporting classes provide bounded logs, deny-list security, unified-diff patching, and control-flow signals for ending tasks, terminating execution, repeating episodes, and moving between episodes.

Processing workflow

  1. Select repository-relative paths, directories, or matcher expressions.
  2. Traverse source, test, documentation, site, and module boundaries.
  3. Use format-specific reviewers to locate actionable guidance.
  4. Compose provider requests from guidance, metadata, templates, and tools.
  5. Execute the configured provider and apply results to files or Act workflows.

Usage

Packaged execution starts the command-line entry point, for example {@code java -jar gw.jar [paths] [options]}. Targets may be paths such as {@code src/main} or {@code src/main/javadoc}, or {@code glob:} and {@code regex:} expressions accepted by {@code java.nio.file.FileSystems#getPathMatcher(String)}.

Prompt content can include external fragments with {@code >>>} markers, substitute public properties such as {@code ${public.projectName}}, and receive process metadata describing the file, operating system, and interactive mode.

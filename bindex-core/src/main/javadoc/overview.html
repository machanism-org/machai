Bindex Core

Bindex Core provides core functions for managing bindex metadata, including library generation, registration, selection, and project building. It enables automated processing of library metadata for efficient application discovery, integration, and assembly workflows.

Bindex Core supports all types of project files—including source code, documentation, project site content, and other relevant files. A Bindex descriptor gives each reusable project, library, or integration a consistent, searchable description.

Package overview

The org.machanism.machai.bindex.core package is the persistence and semantic-selection layer. BindexRepository defines the storage contract; MongoBindexRepository implements it with MongoDB; Picker coordinates classification, embeddings, search, registration, and dependency traversal; and BindexInfo carries compact recommendation results. The package-level documentation describes these responsibilities and the normal repository-to-picker integration.

The org.machanism.machai.bindex.ai.tools package adapts the core services for AI function calling. BindexFunctionTools retrieves descriptors by coordinates or URL, filters JSON with a GraphQL-style selection, recommends libraries, and registers descriptors from files or JSON objects. GraphqlJsonFilter performs the response projection.

Bindex metadata and search

A Bindex is structured JSON, commonly stored as bindex.json. Its identity, name, version, description, classification, and dependency identifiers describe a reusable component. Classification contains domains, architectural layers, programming languages, and integrations; the serialized classification is embedded for semantic retrieval. MongoDB stores the descriptor, filterable classification fields, and its embedding vector.

Typical workflow

  1. Create or update a bindex.json descriptor for a project, library, or integration.
  2. Register it through Picker or register_bindex/register_bindex_json.
  3. Submit a natural-language requirement to Picker.pick or pick_libraries.
  4. The configured GenAI provider classifies the request and the embedding provider creates its vector.
  5. The repository combines vector similarity with language and layer filters, then returns scored results.
  6. Use the returned identifiers with get_bindex; dependencies can be resolved recursively by the picker.

Configuration

  • Maven targets Java release 17; schema classes are generated in org.machanism.machai.schema.
  • MongoDB connection details are resolved by Configurator, including BINDEX_REPO_URL, credentials, database, and collection settings.
  • Embedding generation uses embedding.model and requests 700-dimensional vectors.
  • Classification uses pick.model, falling back to gw.model.
  • The recommendation tools default to score 0.85 and search limit 25.

Usage examples

Register a descriptor and select libraries:

{@code Picker picker = new Picker(repository, configurator); String bindexId = picker.save(bindex); Collection<BindexInfo> matches = picker.pick("Java service using MongoDB", 25, 0.85, configurator);}

Retrieve a stored descriptor with repository.getBindex("org.example:library:1.0.0"). Tool callers can instead use get_bindex with an identifier, HTTP(S) URL, or project-local file:// path and optionally request selected fields.
